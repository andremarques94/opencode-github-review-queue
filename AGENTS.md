# AGENTS.md

This file gives coding agents project-specific context. Keep it short and update it when workflows change.

## Project Overview

- Primary package: `opencode-github-review-queue`, an OpenCode v2 plugin for
  GitHub review requests.
- Main entry points: `src/server/index.ts`, `src/tui/index.tsx`,
  `src/gui/index.tsx`, and `src/rpc/review-queue.ts`.
- Important directories: `src/domain`, `src/server`, `src/rpc`, `src/shared`,
  `src/tui`, `src/gui`, and `test`.

## Architecture Notes

- Module boundaries: keep server, RPC, domain, shared, TUI, and GUI concerns in
  their existing directories. Runtime-specific code must not leak into shared
  modules.
- Generated or vendored code: `dist/` is generated by Vite and is not tracked.
- Sensitive areas: `src/server/github.ts` invokes GitHub CLI directly. Do not
  interpolate pull request data into a shell command or persist credentials.

## Commands

- Install: pnpm install
- Build: `pnpm build`
- Test: `pnpm test`
- Full check: `pnpm check`
- Changed-code audit: `pnpm fallow:audit`

## Fallow

- Use `fallow audit --format json --quiet` before committing AI-generated changes.
- Use `fallow dead-code --format json --quiet`, `fallow dupes --format json --quiet`, and `fallow health --format json --quiet` for targeted checks.
- Use `fallow list --entry-points --format json --quiet` and `fallow list --boundaries --format json --quiet` to inspect project shape.

- Do not edit generated `dist/` output directly.
- Always ask before changing the supported OpenCode or OpenTUI versions.
- Preserve Biome formatting, use braces for every `if`, and prefer the smallest
  change that maintains the runtime boundaries above.

## Fallow checks

Use fallow for code-quality, cleanup, and setup tasks in this repository. Fallow checks the changed code before each `git commit` and `git push`. In Claude Code and Codex, a PreToolUse hook from `fallow agent install` runs this check and blocks the command when the verdict is `fail`. Other agents run the check themselves: `fallow audit --format json --quiet --explain --gate-marker agent`. If the verdict is `fail`, fix the reported findings before you try again. A JSON runtime error such as `{ "error": true, ... }` does not block.

Audit defaults to `gate=new-only`: only findings introduced by the current changeset affect the verdict. Inherited findings on touched files are reported under `attribution` and annotated with `introduced: false`, but do not block the commit. Set `[audit] gate = "all"` in `fallow.toml` to gate every finding in changed files.

For non-skill agents, treat the task map below as the local onboarding source: run the listed fallow command before destructive edits, before commits, and before pull request handoff.
