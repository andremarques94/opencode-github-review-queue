# AGENTS.md

`opencode-github-review-queue` is an OpenCode v2 plugin that lists the GitHub pull requests waiting for the user's
review in the TUI and Desktop app.

## Layout

- `src/domain`: review request (with readiness and who it was requested from), queue and its filter rules, review
  draft, review history (what was last posted), the user's own pull requests (status and notices), and snooze types
  and rules, and the pull request diff parser
- `src/shared`: runtime-neutral code: options, presentation (row readiness marks), the RPC contract,
  `notifications/`, and `review/` (draft status and row labels, post preview, the start/post/reset flows, snooze,
  summary, and Desktop line comments; both UIs run these through their flow host)
- `src/server`: server entry, the polling state machine, the lease that picks the one instance that polls
  (`queue-lease.ts`), the searches and rules that make up the queue (`queue-source.ts`), plain keyed storage
  (`keyed-store.ts`) and snooze pruning, plus:
  - `github/`: `gh` runner, review search, pull requests (states, compare diffs), repository lookup
  - `git/`: `git` runner, remotes, worktrees
  - `review/`: draft storage, review sessions (start, follow-up, reset, post, prune), sessions that address a review
    of the user's own pull request, findings, checkouts, models, summaries, and `agent/` (instructions and the
    `review_*` tools)
- `src/ui/gui`: Desktop entry, `actions/` (review actions and flow host), and `components/` (Solid, scoped stylesheet)
- `src/ui/tui`: TUI entry, `actions/` (review actions, flow host, menu options), and `components/` (OpenTUI)
- `dist/`: generated by `pnpm build`; never edit it

UI components live one per file, grouped by role (`header/`, `list/`, `feedback/`). A directory with a single file
should not exist; keep that file in its parent instead.

Use relative imports (`./header/panel-header.js`, `../../shared/rpc.js`). OpenCode loads these sources with a
resolver that honours neither `tsconfig.json` paths nor `package.json` imports, so an alias such as `@/` fails at
load time even when TypeScript, Vite and Vitest accept it. Adding an alias means adding a build step first.

Plugin storage keys: `baseline` (the queue, the user's own pull requests, and the last poll's notices), `lease`
(which instance polls), `draft/<key>`, `reviewed/<key>`, `snooze/<key>`, and `address/<key>` (the session
addressing a review of the user's own pull request). Only the lease holder fetches from GitHub and prunes; the
others re-read `baseline` each interval.

Keep runtime-specific code out of `src/domain` and `src/shared`. `src/server/github/cli.ts` spawns `gh` without a
shell; never interpolate pull request data into a command or persist credentials.

The Desktop bundle cannot ship CSS, and the host only compiles the Tailwind utilities it uses itself. Style the GUI
through `src/ui/gui/components/styles.ts` with the host's CSS variables. TUI colors come from `context.theme`
(`text.base`, `text.muted`, `text.faint`, `text.action.primary.base`, `text.feedback.<kind>.base`, `background.raised.base`).

## Commands

- `pnpm install`: install dependencies and Husky hooks
- `pnpm check`: typecheck, lint, test, and build
- `pnpm fallow:audit`: changed-code audit; also runs before every `git push`

## Rules

- Ask before changing the supported OpenCode or OpenTUI versions.
- Use braces for every `if`, keep Biome formatting, and prefer the smallest change.
- Prefer `type` over `interface`.
- Avoid `else`; return early instead. Replace a chain of `if`s on the same value with a `switch`.
- Commit messages follow Conventional Commits.

## Fallow

The Fallow MCP server is configured in `opencode.jsonc`. Before deleting code or opening a pull request:

| When you are about to... | Run |
|---|---|
| delete an "unused" export or file | `fallow dead-code --trace <file>:<export>` |
| delete an "unused" dependency | `fallow dead-code --trace-dependency <name>` |
| commit or open a PR | `fallow audit --base <ref>` |
| prioritize refactoring | `fallow health --hotspots --targets` |
| check import cycles and boundaries | `fallow architecture` |
| understand a finding | `fallow explain <issue-type>` |
